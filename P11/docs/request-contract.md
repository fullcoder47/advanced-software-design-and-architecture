# Request contract and failure timeline
Client POST with Idempotency-Key K1 and Correlation-ID trace-1 → server commits R101 → response lost → client retries same key and same canonical payload → returns R101. Different payload using K1: 409 Conflict. One booking is committed within retention. Retry transient/uncertain failures only, with overall deadline, bounded attempts and capped exponential backoff. In production, persist the key, payload hash and result atomically with the booking; scope keys to caller; use a real correlation ID in logs; expiration means replay protection no longer holds.
